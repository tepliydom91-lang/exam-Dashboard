Варіант 5. Дошка задач мінікоманди
Бізнес-сценарій
Невелика команда веде облік задач. Тімлід створює задачі, призначає виконавців, ставить дедлайни і закриває виконане.
Виконавець бачить свої задачі, рухає їх по етапах роботи й пише коментарі про хід виконання.
Ролі та тестові акаунти
Виконавець (member) member@example.com / member123 — тільки свої задачі, обмежена зміна статусу
Тімлід (lead) lead@example.com / lead123 — усі задачі, створення, призначення, закриття
Редірект після входу member → /tasks?assignee=me ; lead → /tasks
Дані
task = {
id, title, description,
assigneeId, assigneeName,
priority, // 'low' | 'normal' | 'high'
status, // 'todo' | 'in-progress' | 'review' | 'done'
dueDate, createdAt, createdBy,
comments: [ { id, text, authorName, createdAt } ]
}
user = { id, name, email, role }
Початковий набір даних
не менше 3 користувачів (1 тімлід + 2 виконавці), щоб було кого призначати;
не менше 8 задач з усіма 4 статусами і 3 пріоритетами;
щонайменше 2 задачі з dueDate у минулому і статусом, відмінним від done ;
не менше 3 задач із коментарями.
Маршрути
Маршрут Що показує
/login форма входу
/tasks список задач; фільтри ?status= та ?assignee=
/tasks/new форма створення задачі (тільки lead)
/tasks/:id картка задачі
/not-found і * сторінка 404
Обов'язкова частина
Тімлід:
бачить усі задачі; може фільтрувати їх за виконавцем і за статусом (обидва фільтри в URL);
створює задачу: заголовок 5–80 символів, опис не менше 10 символів, виконавець обраний зі списку користувачів
(список завантажується з «сервера»), пріоритет обраний, дедлайн не раніше сьогодні;
після створення — редірект на картку задачі;
єдиний, хто може перевести задачу в done і повернути її з review назад у in-progress .
Виконавець:
за замовчуванням бачить тільки свої задачі;
переводить свою задачу по ланцюжку todo → in-progress → review . Кнопка наступного кроку підписана відповідно до
поточного статусу; на статусі review кнопка зникає з підказкою «Очікує перевірки тімліда»;
не може міняти статус чужої задачі — навіть якщо відкрив її за прямим посиланням;
додає коментарі до задач.
Прострочені задачі: задача з дедлайном у минулому і статусом, відмінним від done , позначається у списку
(«Прострочено на N днів»). Обчислюється на клієнті, у даних не зберігається.
Додатково (за бажанням)
Вигляд «колонки»: задачі згруповані по статусах у чотири стовпці з лічильником у заголовку кожного.
Перемикач вигляду «список / колонки», збережений у search params.
